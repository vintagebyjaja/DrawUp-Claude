# Monroe School — approximate existing-site prototype

Personal proof of concept. No DrawUp UI or public functionality. Work is confined to `migration`; no push is authorized until the user approves previews.

## Accuracy and scope

This is an **approximate reference-based model**, not a successful CADmapper import. No verified coordinate reference system, geographic origin, north orientation, surveyed scale, property boundary, terrain elevations or measured building heights are available. The flat ground is a staging surface, not real topography. Every numeric model dimension is an estimate in nominal metres. The aerial screenshot's pixel relationships informed the layout; 5.2 pixels per nominal metre is an arbitrary modeling assumption, not a measured scale.

The model includes estimated existing school blocks, neighboring contextual masses, brick and pale facade framing, repeated windows, flat roofs, individual solar modules, approximate roads, sidewalks, parking, trees and open lawns. Roof equipment, planting, vehicles and facade spacing are schematic. No redesign is included. There is no claim of interiors, construction documentation, structural design, accessibility compliance, historic/current conditions verification or complete context.

School identification comes from the supplied address and reference photographs, not independently verified survey data. Map labels may be offset; adjacent blocks are represented as context rather than asserted to belong to the school. Source reference images are not baked into model textures; the brick texture is generated by the included script.

## Reproduce

Requirements: Blender 4.3.2 with FBX, OBJ and glTF import/export; Python with Pillow for the generated brick texture. Use an existing checkout, without creating a worktree. Keep generated binaries outside the application checkout.

```bash
bash personal-masterplan/run01/scripts/regenerate.sh /workspace/masterplan-run01/regenerated
```

The script creates the editable BLEND, GLB, OBJ/MTL, FBX and four PNG renders, then independently reopens/reimports all four formats. Validation checks nonempty mesh geometry, finite coordinates, nondegenerate faces, material assignment, available image references, triangle counts and world-space bounds. It verifies export fidelity relative to this approximate model, **not accuracy against the real site**. Read `validation/SUMMARY.json`; retain failed checks rather than treating file existence as success.

Collections distinguish original-source status (empty because SKP was not imported), estimated flat terrain, approximate existing buildings, paving, landscape, roof/solar details, facades, presentation cameras/lights and materials. The proposed-buildings collection is empty. Mesh objects remain editable; repeated forms share mesh data where appropriate. Use Blender's Make Single User operation before changing one repeated component independently. BLEND packs the brick image. GLB embeds its image; the OBJ uses an accompanying MTL and relative texture file. FBX includes an embedded texture and may unpack a `.fbm` directory on import.

## SKP conversion investigation

Source header: SketchUp `{15.0.1}`. Native SKP and DAE import operators are absent in this Blender build. The open-source [SketchUp Importer](https://github.com/RedHaloStudio/Sketchup_Importer) was inspected at commit `fd98910949321c89ca7cc43c42ecb4e665362eb9`. Its README explicitly excludes Linux due to unavailable SketchUp SDK libraries. Its Cython and Rust bindings both link against SketchUpAPI; a Linux container does not remove that dependency. An actual Blender module-load attempt failed because its compiled `sketchup` binding is absent. Wine is not installed, and no licensed Windows/macOS SketchUp converter is supplied. No conversion succeeded. The fallback is explicitly authorized by the latest chat request.

The original SKP and its license remain unchanged. A later supported conversion to FBX, OBJ/MTL or GLB can replace this estimated baseline after unit, origin and coverage checks. Do not overwrite the original source with fallback geometry.

## Delivery and review

Generated files are delivered as a separate downloadable ZIP, with an inventory and SHA-256 hashes. Scripts, report, validation summary and preview copies form the reviewable repository changes. Large working binaries remain outside Git; they must not be pushed as ordinary repository blobs. After approval, choose Git LFS for tracked binary assets or a release artifact for the ZIP, and review the exact upload destination. No GitHub preview URL can exist for these local changes until a permitted publication operation occurs; local renders and a saved patch provide the pre-push review.
