# DrawUp v23.2: Quick Check, faster Check, Cloudflare, sign-in fix

## v23.2: sign-in works again with no Cloudflare changes
- Your Supabase URL and key reach the site at build time (as Build variables). v23.1 only looked for them while the site runs, so it couldn't find them. That was my mistake, and you didn't delete anything. v23.2 uses the build-time copy again, and the runtime Variables still win if you ever add them. Tested both ways on the Cloudflare runtime.
- wrangler.jsonc now also has `"keep_vars": true`. Without it, each deploy deletes any plain-text Variables typed into the Worker's dashboard settings (Secrets are kept). This protects them if you add some later.
- Nothing to do in Cloudflare. After deploying, https://drawup.studio/api/supabase-config should show your Supabase URL and `"missing":[]`. Only if it still says missing, use the steps below.

### Only if sign-in still says "missing": add the two settings
1. Supabase dashboard → your project → **Project Settings → API** (or **Connect**). Copy the **Project URL** and the **anon public** key (or the **publishable** key).
2. Cloudflare dashboard → **Workers & Pages** → **drawup-aec** → **Settings** → **Variables and Secrets** → **+ Add**.
3. Type **Text**, Variable name `NEXT_PUBLIC_SUPABASE_URL`, value = the Project URL (for example https://abcd1234.supabase.co, no quotes, no trailing slash). **Deploy**.
4. **+ Add** again: Type **Text**, name `NEXT_PUBLIC_SUPABASE_ANON_KEY`, value = the anon public key. **Deploy**.
5. Check that `OPENAI_API_KEY` and `SUPABASE_SERVICE_ROLE_KEY` are still listed there as Secrets. If either is missing, add it with Type **Secret**.
6. Optional, as a backup: **Settings → Build → Variables and secrets** → add the same two names and values there too.
7. Open https://drawup.studio/api/supabase-config. It should show your URL and `"missing":[]`. Then sign in.


## v23.1 fixes (sign-in and Connect)
- **Sign in could stop working without any message.** The browser gets its Supabase settings from `/api/supabase-config`. Next.js bakes `NEXT_PUBLIC_…` values in at build time whenever they exist as Cloudflare *Build* variables, and those baked-in values override the Worker's runtime Variables. A missing or mistyped build value meant the page had no database connection, so the Sign in button did nothing and Connect said "database is not connected". Settings are now read when the request runs, with stray spaces and quotes removed, so the Worker's Variables win over a build value.
- The Sign in button now always answers. If it can't connect, it tries again, loads the sign-in library from a backup CDN, and shows the reason (for example "missing NEXT_PUBLIC_SUPABASE_URL") instead of doing nothing.
- The Supabase sign-in library is pinned to version 2.117.2 instead of "whatever is newest", so a new release can't change the site without a deploy.
- **Connect is members only and lives in the portal.** On the public site, visitors see "Join Free Agency to Connect." with Join Free Agency and Sign in buttons. Signed-in members see "Connect lives in your portal." with an Open Connect button. Message and post buttons elsewhere on the site take members straight to Connect inside the portal.


## What's new
- **Quick Check is back as one step.** It sits at the top of the Check tab, and `#portal/check?quick=1` jumps straight to it. You upload an image, PNG, JPG or PDF set (up to 12 pages) and pick a sheet template. Press **Check it** and you get:
  1. **Find the flaws.** Each problem shows up while it is being written.
  2. **Understand the fix.** For each problem you get what's wrong, why it matters and the change to make.
  3. **On your template.** Your drawing is placed on the template you picked with each fix drawn in green, and the revisions are listed in the title block. You can switch the view between Corrected, Redlines + fixes and Original, and download the result as a PDF.
- **Templates:** DrawUp ARCH D (36×24), ARCH E1 (42×30), Tabloid (11×17), Letter, or **My template**, where you upload your own blank sheet with your title block (PDF/PNG/JPG) and say whether the title block is on the right or the bottom. DrawUp saves it for next time.
- **Why Check was slow, and the fix.** Your current Check reviews one sheet at a time. Each sheet is a separate OpenAI background job running on the slower default reasoning effort, and the page only moves on to the next sheet when it polls. The progress screen also never showed findings until every sheet was done, so a 3-page set could sit at 90% with "Nothing written yet" for many minutes. Quick Check skips all of that: the page turns each sheet into images (plus close-up quarters so small text is readable), and the answer streams straight back on the same request, so there is no queue and no polling. It uses a faster model (gpt-5-mini, falling back to gpt-5) with low reasoning effort. On the test setup the first problem showed up in about 2 to 3 seconds. Real OpenAI timing will be longer, so expect roughly a minute for a few sheets.
- **The full Check is faster too.** Your sheet-by-sheet review now uses low reasoning effort per sheet and no web search by default, and its progress screen shows each sheet's findings as soon as that sheet is done.
- **Safety:** if you close the page in the middle of a Quick Check, the check is marked failed and your credits are refunded after 15 minutes, so it can't hang forever. If an answer gets cut off, the problems found so far are kept and you are not charged.
- Every Quick Check is saved in **Your checks**, so it opens later in the full viewer.

## Cloudflare settings
- Keep your current build and deploy commands (`npm run build:cloudflare`, `npm run deploy:cloudflare`).
- **Use the Workers Paid plan.** The Free plan gives each request 10 ms of CPU, which Check cannot fit in: reading a PDF with pdf-lib for each sheet and sending pages to the AI takes far longer. On Free, sheet reviews can be cut off silently and restart, which looks exactly like sitting at 90% with nothing written. Paid gives 30 seconds per request.
- Secrets (Worker → Settings → Variables and Secrets, type Secret): OPENAI_API_KEY, SUPABASE_SERVICE_ROLE_KEY, CRON_SECRET if used.
- Variables (runtime, under Worker → Settings → Variables and Secrets): NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY (or NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY). Build variables are optional backups. wrangler.jsonc keeps dashboard Variables across deploys from v23.2 on.
- Optional: DRAWUP_CHECK_QUICK_MODEL (default gpt-5-mini, then gpt-5), DRAWUP_CHECK_QUICK_EFFORT (minimal / low / medium, default low), DRAWUP_CHECK_EFFORT (per-sheet effort for the full check, default low), DRAWUP_CHECK_WEB_SEARCH=on.
- In Supabase Auth → URL Configuration, add your Cloudflare address to the allowed redirect URLs if sign-in links still go to Netlify.
