# DrawUp v25.1: Cloudflare error 1102 fix + Draw a detail

v25.1 is built on v25 and has two parts:
- **The Cloudflare CPU fix** for the home page and Draw it up.
- **Draw a detail** on the Details tab.

It's 15 files (2 of them are the SQL kept in the repo), plus 2 SQL files to run. Nothing was deployed to Cloudflare or run on your Supabase.

## Deploy in this order
1. Run the 2 files in `sql-run-in-order/` in Supabase → SQL Editor, one at a time and in order:
   - **v25.1-01** prints "DONE v25.1 drawing background jobs".
   - **v25.1-02** prints "DONE v25.1 AI details in the Detail Catalog".

   Both are safe to run twice and add columns only. Both were run twice on Postgres 16.
2. Copy everything in `files/` over your repo, keeping the same folders:
   - `public/index.html` (new): the home page as a static file, so the Worker no longer runs for it.
   - `public/drawup-drawit-v24.js` + `.css`: Draw it up runs jobs in the background, has catalog links on needed details, and a "Draw a single detail" link.
   - `public/drawup-detail-draw-v25.js` + `.css` (new): the **Draw a detail** panel and the AI detail viewer.
   - `public/drawup-details-v21.js`: the catalog gets a **Drawn by DrawUp AI** section and filter.
   - `public/drawup-details-kit-v21.js`: the title block can say "DRAWUP AI DETAIL".
   - `public/drawup-detail-reviews-v24.js`: comments and architect checks also work on AI-drawn details.
   - `public/drawup-preview.html`: tag lines only. Two new tags were added, and the changed files are now `?v=25.1`.
   - `src/app/api/drawings/generate/route.ts`: background jobs and stored picture links. It also offers the catalog's AI details to the AI.
   - `src/app/api/details/draw/route.ts` (new): the Draw a detail API.
   - `src/lib/drawup-detail-draw.ts` (new): the detail prompt, schema and limits.
   - `src/lib/drawup-server.ts`: adds 2 helpers (`storageSignedUrls`, `openaiBackground`). Supabase settings are read exactly as before.
   - `supabase/migrations/0066…`, `0067…`: the same SQL as step 1, kept with the repo.
3. Deploy as usual: `npm run build:cloudflare`, then `npm run deploy:cloudflare`.
4. Hard-refresh drawup.studio.

`wrangler.jsonc` is untouched, so `keep_vars` stays on and your Supabase variables are kept.

## Draw a detail (Details tab)
- **The upload panel.** The Details tab opens with **Draw a detail · Find the flaws · Clean redraw**.
  - Drop a PNG, JPG or WebP, or a PDF of up to 4 pages. Add what you know: sizes, climate, code.
  - Choose whether it goes in the catalog for everyone (the default) or stays private.
  - Press **Find the flaws + draw the clean detail**.
- **What you get back:**
  - Your upload, and what DrawUp read in it.
  - Every flaw, most serious first. Each one has its severity, **why it matters**, **the fix**, and a code or standard reference. Section numbers DrawUp isn't sure of say "verify".
  - General notes and assumptions.
  - **One clean detail drawing** with hatched materials, leader notes, dimensions, the detail bubble and a title block. It is drawn at a standard architectural scale (3" down to 1/8" = 1'-0"), using the largest scale that fits. The **PDF is 8 x 6 in and prints true to that scale**. PNG and SVG work too.
- **It is one detail, not a set.**
- **DWG, DXF, RVT, RFA, IFC and SKP can't be read directly.** Those are CAD or BIM model files that need AutoCAD or Revit to open, so neither the browser nor the AI can read them. If you drop one, the panel says so and explains how to export the detail view to PDF or an image (AutoCAD: plot to PDF; Revit: Export → PDF or Images).
- **Detail Catalog:**
  - The clean detail is saved to `details` as a community **AI-drawn** detail with a code like `AI-3D2C5`.
  - It appears under **Drawn by DrawUp AI from member uploads** and has its own source filter.
  - Opening it shows the drawing, the flaws and fixes, and the downloads. The owner can switch it between private and the catalog, and HQ can hide it.
  - Comments and architect checks from v24 work on it.
- **Referenced on future drawings:**
  - When a new Draw it up set is made, the catalog's AI details are offered to the AI. A set that needs one names it by its code, so the code appears in the A5xx detail list on the sheets.
  - On the set page, each "Detail this set still needs" links to the matching catalog detail (an AI-drawn one first, then a DrawUp typical). If there's no match, it says "Not in the catalog yet: draw it from a picture".
- **Runs like Draw it up:** a background job with check-ins every 4 seconds, about 15 ms of Worker CPU per request in testing. If you close the tab, it's collected the next time you open Details.
- **Credits:** **15 per detail (new price, please confirm).** You can change it with the Cloudflare setting `DRAWUP_DETAIL_DRAW_COST`. Unlimited and HQ accounts aren't charged, and a failed job is refunded once. Optional settings: `DRAWUP_DETAIL_MODEL` and `DRAWUP_DETAIL_EFFORT`.

## What was wrong
I rebuilt v25 with your Cloudflare build (OpenNext), ran it in Cloudflare's local runtime, and measured the Worker CPU each request used. Local CPU speed differs from Cloudflare's, so treat these numbers as estimates.

| Request | v25 | v25.1 |
|---|---|---|
| `GET /` (home page) | ~33 ms each time, ~350 ms on a cold start | **0 ms**: a static file, so the Worker doesn't run |
| `POST /api/drawings/generate` (one full set, 3 photos) | **~730–920 ms** in a single request | about 16–20 ms to start, ~11 ms for each check-in, ~23 ms for the request that saves the set |
| Any small API route (for example `/api/supabase-config`) | ~8 ms warm, ~350 ms on a cold start | unchanged (this is Next.js's own overhead) |

- **Home page.** `src/app/page.tsx` only draws a full-screen frame around `drawup-preview.html`. The build marks it static, but OpenNext has no page cache set up, so Next.js rendered it again on every visit (~33 ms). Now `public/index.html` does the same thing. Cloudflare serves it straight from your static files, the same way it already served `drawup-preview.html`, so the Worker never starts for it. Sign-in links (`?code=…`, `#access_token=…`) and deep links (`#portal/…`) are still passed through, and one-time tokens are still cleared from the address bar. `page.tsx` stays in the repo and still works in `npm run dev`.
- **Draw it up.** Three things added up:
  - **Relaying the AI's streamed answer (the main cost).** About 6,000 small pieces came through the Worker, and each one also sent a progress line to the page. That alone was ~0.7 s of CPU.
  - **Reading the request.** The 1–6 photos arrived again as base64 text, 3–6 MB in each request, even though the page had already uploaded them to Supabase Storage. Reading that text took another 20–50 ms.
  - **Sending it to OpenAI.** The same megabytes were written out again to send them on.

  There were no infinite loops. Drawing the sheets and building the PDF already happen in the browser, not in the Worker.

## What changed in Draw it up
- **Pictures go as links.** The AI gets 1-hour signed links to the photos your page already uploaded (`drawup-private/{you}/drawings/…`). Comment crops on a revision are uploaded the same way. A picture is only sent in the request if its upload failed.
- **The AI runs as a background job at OpenAI**, the same way v25's AI Team jobs already work.
  - The first request reserves the credits, starts the job and returns a signed ticket right away.
  - The page checks in every 4 seconds. Each check-in is one quick status read.
  - The check-in that finds the finished answer saves the set, adds its details to the library and awards XP. It does this exactly once.
  - A failed job is refunded once.
- **Survives leaving the page.** The ticket is kept in the browser. If you close the tab, the job keeps running, and the next time Draw it up opens it collects the set ("Finishing the drawing set you started earlier…").
- **Unchanged:** the endpoint (`/api/drawings/generate`), the request fields, prices, modes (Preliminary, Full, Explore), revisions and redlines, Develop, the saved rows, and what the page shows. A browser still running the old v25 script gets the old streaming answer. That path now sends at most 2 progress lines a second, which cut it from ~750 ms to ~230 ms.

## Do you need Workers Paid? Yes, for the AI features
- **Free plan: 10 ms of CPU per request.** After v25.1, the home page needs no Worker at all, so it works on Free.
- **Every API route still runs Next.js inside the Worker.**
  - That costs ~8 ms even for a trivial route, and ~350 ms the first time a fresh Worker instance handles a request (a cold start).
  - Draw it up's requests are now ~11–23 ms each.
  - Sign-in setup (`/api/supabase-config`), Arch Coach, AI Team, Check and Draw it up will all keep hitting 1102 on Free, mostly on cold starts.
  - No code change gets a Next.js API under 10 ms reliably.
- **Workers Paid is $5/month.** It includes 10 million requests and 30 million CPU-ms a month, with a default limit of 30 seconds of CPU per request. After v25.1 the heaviest DrawUp request uses well under 0.1 s, so you don't need to raise the limit or set `limits.cpu_ms`. Leave `limits` out of `wrangler.jsonc` on the Free plan, which doesn't allow a custom CPU limit.
- **Other routes that are heavy but fine on Paid.** I didn't change these, because they weren't in the errors:
  - AI Team chat and Arch Coach relay streamed answers the same way Draw it up used to.
  - Check splits PDFs with pdf-lib in the Worker.

## Tested (locally, with stand-ins for Supabase and OpenAI)
- **Draw a detail in Chromium:**
  - A DWG showed the export message.
  - Uploading a picture gave a running job, then the flaws, fixes and clean detail. The PDF downloaded.
  - The detail showed in the catalog's AI section.
  - Matching a needed detail found it by code and by name.
  - A Draw it up ticket is refused by the detail route.
  - Previews are in `previews/`.
- **Home page:** `GET /` is served from the static files. In Chromium, `/?code=abc#portal/profile` opened `drawup-preview?code=abc#portal/profile` inside the frame and cleared the code from the address bar. The site rendered normally.
- **New set** (3 stored pictures, background): the start returned a ticket, the check-ins returned "running", and then "done" with the saved set. The AI request was 9 KB instead of 2.9 MB.
- **Revision** with a comment crop sent as a link: saved as Rev 1 with its parent and comments.
- **Old-style request** (base64 pictures, no background): still streams and saves.
- **Bad tickets and other members' storage paths are refused.**
- **TypeScript compiles and the OpenNext build passes.**

**Not tested:** a live OpenAI call, real Supabase Storage links, and Cloudflare's own CPU accounting. After you deploy, open Workers & Pages → drawup-aec → Observability and check the CPU time for `GET /` (it should disappear) and `/api/drawings/generate`.
